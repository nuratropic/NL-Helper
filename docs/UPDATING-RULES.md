# Как обновить правила в скрипте

Когда на форуме меняются правила, скрипт показывает кураторам уведомление. Чтобы шаблоны снова совпадали с форумом, обновите таблицы в `src/` и выпустите новую версию.

## 1. Найти изменения

Источник — раздел [«Правила серверов»](https://forum.blackrussia.online/categories/%D0%9F%D1%80%D0%B0%D0%B2%D0%B8%D0%BB%D0%B0-%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%BE%D0%B2.50/). Администрация публикует изменения отдельным сообщением в теме правил в формате «Было / Стало» и указывает дату вступления в силу. Первое сообщение темы обычно уже отредактировано под новую редакцию.

| Что изменилось | Где править |
|---|---|
| Общие правила серверов (тема 312571) | `src/04-rules-general.js` → `RULE_TABLE` |
| Правила гос. организаций (655011) | `src/05-rules-orgs.js` → `GOV_TABLE` |
| Правила криминальных организаций (3353981) | `src/05-rules-orgs.js` → `CRIM_TABLE` |
| Правила и обязанности лидера (202392) | `src/05-rules-orgs.js` → `LEADER_TABLE` |
| Правила подачи жалоб/обжалований, биографий, ситуаций, организаций | шаблоны в `src/03-templates.js`, требования к биографии — `BIO_RULES` в `src/02-config.js`, формы жалоб — `FORM_FIELDS` в `src/14-wizard.js` |

## 2. Править таблицу

Одна строка — один пункт:

```js
['2.04', 'Описание пункта', 'Наказание', 'Короткое имя', 'теги, для, поиска'],
```

- **Номер** пишется как на форуме. Примечание со своим наказанием — тот же номер с буквой «п» (`'2.19п'`).
- **Описание** — суть пункта одной фразой (длинные примеры и исключения не нужны: они есть на форуме).
- **Наказание** — дословно, как после `|` на форуме.
- **Короткое имя** — 1–3 слова для заголовка карточки.
- **Теги** — сленг и слова, которыми игроки описывают нарушение: по ним мастер подбирает пункт.

> [!IMPORTANT]
> В `RULE_TABLE` **не меняйте порядок и не удаляйте основные пункты** без необходимости: из их порядка строятся id шаблонов (`p10_a`, `p11_d`…), к которым привязаны счётчики использований и история кураторов. Новый основной пункт добавляйте в конец своего раздела и проверьте тестами, что id старых пунктов не сдвинулись (тест «id шаблонов совпадают с прошлыми версиями»). Примечания (`…п`) на id не влияют.

Если удалённый на форуме пункт нужно убрать, лучше оставить его строку с пометкой в описании («утратил силу») до следующей мажорной версии.

## 3. Обновить даты редакций

- `RULES_REVISION` в `src/01-core.js` — дата вступления в силу новой редакции (видна кураторам в окне и в уведомлениях).
- `RULE_WATCH` в `src/09-dialogs.js` — дата последнего сообщения в изменившейся теме (её видно в списке тем раздела). Иначе уведомление об «обновлении» продолжит показываться.
- Комментарии с датами редакции над таблицами.

## 4. Проверить и собрать

```bash
npm test          # таблицы, посты, подбор пунктов, миграция
npm run build     # собрать nl_helper.js
npm run stand     # посмотреть вживую на локальном стенде
```

Поднимите версию в `src/00-meta.js` (`@version`) и `src/01-core.js` (`VERSION`) — сборка проверяет, что они совпадают — и в `package.json`. Опишите изменения в `CHANGELOG.md`.
